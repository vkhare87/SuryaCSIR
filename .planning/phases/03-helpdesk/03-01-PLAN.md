1. **createTicket(params: { subject: string; category: string; urgency: string; description: string; submitted_by: string })**:
   - Call `supabase.rpc('helpdesk_create_ticket', { p_subject, p_category, p_urgency, p_description, p_submitted_by })`
   - On success: return `{ success: true, data: { ticketId: data } }` (RPC returns uuid)
   - On error: return `{ success: false, error: error.message }`

   - Call `supabase.rpc('helpdesk_update_status', { p_ticket_id, p_new_status, p_actor_id })`
   - RPC returns void — success is absence of error

3. **addResponse(params: { ticketId: string; authorId: string; message: string })**:
   - Call `supabase.rpc('helpdesk_add_response', { p_ticket_id, p_author_id, p_message })`
   - RPC returns uuid of new response row
   - Return `{ success: true, data: { responseId: data } }` or `{ success: false, error: error.message }`
   - NOTE: This RPC will be created by Plan 03-02. If the RPC doesn't exist yet during dev, the call will fail gracefully with the error message.

4. **assignTicket(params: { ticketId: string; newHandlerId: string; actorId: string })**:
   - Call `supabase.rpc('helpdesk_assign_ticket', { p_ticket_id, p_new_handler_id, p_actor_id })`

   - NOTE: This RPC will be created by Plan 03-02.

Pattern (follows RESEARCH.md code example):
```typescript
import { supabase } from '../../utils/supabaseClient';

export async function createTicket(params: { ... }): Promise<{ success: boolean; error?: string; data?: unknown }> {
  if (!supabase) return { success: false, error: 'Supabase not configured' };
  const { data, error } = await supabase.rpc('helpdesk_create_ticket', {
    p_subject: params.subject,
    p_category: params.category,
    p_urgency: params.urgency,
    p_description: params.description,
    p_submitted_by: params.submitted_by,
  });
  if (error) return { success: false, error: error.message };
  return { success: true, data: { ticketId: data } };
}
```

No default export. All 4 functions are named exports.

Create `src/lib/helpdesk/routing.ts`:

Import type from types. Export a single pure function:

**resolveRoutingPreview(params: { category: string; routingEntries: HelpdeskRouting[]; divisions: DivisionInfo[]; staff: StaffMember[] }): { handlerName: string; handlerRole: string; category: string; targetType: string } | null**

Logic (client-side mirror of route_ticket() DB function):
1. Find routing entry where `routingEntries.find(r => r.category === params.category)`
2. If found and target_type === 'role': handlerName = target_id (role name), handlerRole = target_id
3. If found and target_type === 'division': find division with `d.divCode === entry.target_id`, then find staff member where `s.ID === d.divHoDID`. handlerName = s.Name, handlerRole = 'DivisionHead'
4. If no routing entry found: return null
5. Return `{ handlerName, handlerRole, category, targetType }`

All data comes from `useData()` context — no Supabase calls. Pure client-side preview.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | ticketRPCs.ts | mitigate | RPCs use `p_actor_id` parameter — the actual authorization check happens in the SECURITY DEFINER RPC server-side (e.g., RPC can verify `p_author_id = auth.uid()`). Client just passes the value. |

| T-03-04 | Elevation of Privilege | permissions.ts | mitigate | ADMIN_ROLES constant restricted to HRAdmin/SystemAdmin/MasterAdmin. canViewAllTickets/canReassign/canForceClose all gate on this set. User cannot escalate client-side — Supabase Auth role mapping is server-authoritative. |
