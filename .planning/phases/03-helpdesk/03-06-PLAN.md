**Add routes** (insert after the committee routes block, before `/recruitment` route):

The committee routes end at line 117. Insert the helpdesk block immediately after line 117, before line 118 (`<Route path="/recruitment" ...`):

```tsx
            {/* Helpdesk — specific routes first (Pitfall 3) */}
            <Route path="/helpdesk/new" element={<ProtectedRoute><TicketForm /></ProtectedRoute>} />
            <Route path="/helpdesk" element={<ProtectedRoute><Helpdesk /></ProtectedRoute>}>
              <Route path=":ticketId" element={<ProtectedRoute><TicketDetail /></ProtectedRoute>} />
            </Route>
```

**Route ordering rationale (Pitfall 3):**
- `/helpdesk/new` is registered first as a standalone route so "new" is never captured as a `:ticketId` parameter
- `/helpdesk` is a layout route with a nested `:ticketId` child — on desktop this renders Helpdesk (left panel) with TicketDetail (right panel via Outlet); on mobile users navigate to `/helpdesk/:ticketId` and see TicketDetail with its own back button
- All three routes are wrapped in `<ProtectedRoute>` without `allowedRoles` — any authenticated user can access helpdesk (matches ROADMAP Phase 3 success criteria)

The existing code at lines 116-118 of App.tsx is:

