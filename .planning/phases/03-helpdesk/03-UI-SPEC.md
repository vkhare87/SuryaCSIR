## Spacing Scale

Declared values (8-point scale, multiples of 4 — standard Tailwind 4 defaults):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge inner spacing |
| sm | 8px | Compact element spacing, button icon margins |
| md | 16px | Default element spacing, section gaps (`gap-4`) |
| lg | 24px | Card padding (`p-6`), section padding |
| xl | 32px | Layout gaps, page section separators |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing, hero sections |

Exceptions: none — standard 8-point scale sufficient for all Phase 3 layouts.

**Context:** Tailwind 4 uses `--spacing` scale; the project does NOT override it. All existing components (Button, Card, Modal, CommitteeList) use these values. Phase 3 pages inherit this scale unchanged.

## Typography

| Role | Size | Weight | Line Height | Family | Usage |
|------|------|--------|-------------|--------|-------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 | Inter, system-ui | Ticket descriptions, response text, filter labels, form fields |
| Label | 12px (`text-xs`) | 500 (medium) | 1.5 | Inter, system-ui | Badges, metadata, timestamps, section captions |
| Heading | 20px (`text-xl`) | 500 (medium) | 1.2 | Georgia, serif | Page titles, ticket token display, section headers |
| Display | 28px (`text-3xl`) | 500 (medium) | 1.2 | Georgia / JetBrains Mono | KPI values (mono), ticket detail token (mono) |

**Weight rationale:** The project uses exactly two functional weights:
- **400 (regular)** — body text, form fields, response content
- **500 (medium)** — headings, labels, badges, buttons (via `font-[500]`)

These are the only two weights used across all existing SURYA components and Phase 3 follows this convention.

**Source:** `src/index.css` line 88 (`line-height: 1.60` for body inherited; Phase 3 explicitly sets `1.5` for ticket content areas). Heading line-height `1.2` from `.heading` utility class. `font-[500]` pattern from existing CommitteeList, CommitteeDetail, Modal headings.

**Serif headings:** All page titles and section headings use the `.heading` utility (`font-serif font-[500] line-height: 1.20`) — match existing CommitteeList, CommitteeDetail, MeetingDetail patterns.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Create Ticket** (button on `/helpdesk`, navigates to `/helpdesk/new`) |
| Submit ticket CTA | **Submit Ticket** (button on TicketForm) |
| Reply CTA | **Reply** (expands reply input); **Submit Reply** (submit button within expanded input) |
| Reply & Resolve CTA | **Reply & Resolve** (secondary button next to Submit Reply — submits response text then transitions ticket to Resolved) |
| Empty state — ticket list (no tickets at all) | **No tickets yet.** Create your first helpdesk ticket to get started. [action: Create Ticket button] |
| Empty state — ticket list (no matching filters) | **No tickets match your filters.** Try adjusting the status, category, or urgency filters. [action: Clear all filters link] |
| Empty state — ticket detail (no selection) | **Select a ticket** from the list to view its details and responses. |
| Empty state — no responses | **No responses yet.** Be the first to respond to this ticket. [action: Reply button] |
| Error state — ticket creation failure | **Failed to create ticket.** {error message}. Please try again. If the problem persists, contact your system administrator. |
| Error state — response submission failure | **Failed to submit response.** {error message}. Your draft has been preserved — please try again. |
| Error state — status transition failure | **Failed to update ticket status.** {error message}. The ticket state may have changed — refresh the page to see the current status. |
| Destructive action — Force Close | **Force Close Ticket:** This will immediately close the ticket regardless of its current status. This action cannot be undone. [Confirm Force Close / Cancel] |
| Destructive action — Reopen | **Reopen Ticket:** This will move the ticket back to In Progress. [Confirm Reopen / Cancel] |
| Submission success | **Ticket created** — {AMPRI-YYMMDD-XXX}. Routing to {handler name}. [View Ticket / Create Another] |
| Response success | **Response submitted.** The ticket handler has been notified. |
| Routing preview label | **Will be routed to:** {handler name} ({role}) — based on {category} category mapping |
| Category grid header | **What best describes your issue?** |
| Urgency selector label | **How urgent is this?** |
| Admin tray — label | **Admin Actions** |
| Admin tray — reassign button | **Reassign Handler** (opens modal with StaffPicker) |
| Admin tray — force close button | **Force Close** (opens confirmation modal) |
| Collapsible timeline toggle | **Ticket Timeline** (chevron toggle; collapsed by default if > 5 events) |
| Segmented status filter labels | **All \| Open \| In Progress \| Resolved \| Closed** |
| Assignment tabs | **My Tickets** \| **Assigned to Me** (+ **All** for admin roles) |

**Copy principles:**
- Verb + noun for all CTAs (Action-oriented)
- Empty states explain what's missing AND what to do next
- Error states describe the problem AND the recovery path
- Destructive confirmations name the action AND its consequence
- No personal pronouns ("you" is acceptable for institutional tool)
- Ticket tokens displayed in monospace font (`AMPRI-YYMMDD-XXX`)

**Source:** All copy is Claude's Discretion per CONTEXT.md — no upstream artifacts define exact copy. Follows SURYA's institutional-professional tone. Matches CommitteeList empty state pattern ("No committees match your filters" → "Clear all filters").

## Interaction Contracts

### 1. Ticket List Filtering (Helpdesk.tsx left panel)

Per D-01: Segmented controls + dropdown for filters.

**Status filter:** Horizontal segmented control
- Segments: All | Open | In Progress | Resolved | Closed
- Active segment: `bg-terracotta text-ivory` (inverted)
- Inactive segment: `bg-surface border border-border text-text-muted hover:bg-surface-hover`
- Behavior: single-select (tapping a segment replaces the active filter)
- Default: "My Tickets" tab shows all statuses (All selected)

**Category filter:** Dropdown multi-select
- Trigger: `bg-surface border border-border rounded-lg` with Filter icon + label "Category"
- Dropdown panel: checkbox list of 8 categories (Infrastructure, Equipment/IT, Administrative, HR/Grievance, Finance, Lab/Research, Library, Transport)
- Multi-select: checkboxes — user can select any combination
- Clear behavior: "Clear" link at bottom of dropdown resets all selections
- Default: all categories selected (no filter)

**Urgency filter:** Dropdown multi-select
- Trigger: same style as Category
- Dropdown panel: checkbox list of 4 urgency levels (Critical, High, Medium, Low)
- Multi-select: checkboxes
- Default: all urgency levels selected (no filter)

**Assignment tabs (D-02, D-04):**
- "My Tickets" (default) — tickets where `submitted_by === user.id`
- "Assigned to Me" — tickets where `assigned_to === user.id`
- "All" — visible only to HRAdmin/SystemAdmin/MasterAdmin; shows all tickets unfiltered by ownership
- Tabs rendered as horizontal button group (same style as status segments but visually distinct)

**Sort order (D-03):** List auto-sorted by urgency (Critical → High → Medium → Low) then by `created_at` descending within each urgency band.

### 2. Ticket Creation Form (TicketForm.tsx at /helpdesk/new)

Full-page form (not modal — per design spec route definition).

**Category grid (Claude's Discretion — button grid):**
- 8 equal-width buttons in a 2-column grid (4 rows x 2 cols on desktop, 1-col on mobile)
- Each button: `Card` with category name + lucide-react icon
- Selected: `border-2 border-terracotta bg-surface` with ring accent
- Unselected: `border border-border bg-surface hover:border-terracotta/30`
- Icons per category:
  - Infrastructure: `Building2`
  - Equipment/IT: `Monitor`
  - Administrative: `FileText`
  - HR/Grievance: `Users`
  - Finance: `DollarSign`
  - Lab/Research: `FlaskConical`
  - Library: `Library`
  - Transport: `Car`

**Form fields (below category grid):**
- Subject: text input, `bg-surface border border-border rounded-lg`, placeholder "Brief summary of your issue..."
- Urgency selector: 4-button segmented control (same style as status filter) — Critical | High | Medium | Low. Default: Medium.
- Description: textarea, `bg-surface border border-border rounded-lg`, min 4 rows, placeholder "Describe your issue in detail..."
- Routing preview (D-02 requirement): Read-only info row below description — "Will be routed to: {handler name} ({role})" — updates reactively when category selection changes. Uses `src/lib/helpdesk/routing.ts` client-side lookup.

**Submit:**
- "Submit Ticket" primary Button at bottom
- On success: redirect to `/helpdesk/:newTicketId` or show inline success with token + routing info
- On failure: inline error message above submit button

### 3. Response Thread (TicketDetail.tsx top ~70%)

Per D-05: Support-ticket post style.

**Each response post:**
```
┌─────────────────────────────────────────────┐
│ [Author Name]  [Role Badge]  ·  [Timestamp] │  ← header row
│                                             │
│ Response message text...                    │  ← body
│ (multi-paragraph, full-width)               │
└─────────────────────────────────────────────┘
```
- Full-width card, not alternating sides
- No chat bubbles, no avatars
- Author name in `font-medium text-text`
- Role badge using existing `Badge` component (info variant)
- Timestamp in `text-xs text-text-muted` — format: "10 May 2026, 14:30 IST" (`en-IN` locale)
- Separator between posts: `border-b border-border`
- Newest response at bottom (chronological order)
- Scroll to bottom on new response submission

**Original ticket "post":**
- First item in the response list — displays ticket subject, description, author, and initial routing info
- Visually distinct from responses: slightly different background or "Original Ticket" label

**Reply input (D-07 — collapsible):**
- Collapsed state: "Reply" button (secondary variant) fixed at bottom of response thread
- Expanded state (via framer-motion `<AnimatePresence>`): textarea + two buttons
  - Textarea: `bg-surface border border-border rounded-lg`, 3 rows min, placeholder "Type your response..."
  - "Submit Reply" button: primary variant
  - "Reply & Resolve" button: secondary variant (visible only when ticket is Open or InProgress AND user is handler)
  - "Cancel" button: ghost variant, collapses back to button
- Draft preservation (Pitfall 6): reply text stored in `useState` lifted above the collapse toggle — text persists when toggling visibility

**Status transition buttons (visible to handler, below reply area):**
- If status = Open: "Mark In Progress" button
- If status = InProgress: "Resolve Ticket" button
- If status = Resolved AND user = submitter: "Close Ticket" button
- All transition buttons call `helpdesk_update_status` RPC via `ticketRPCs.ts`

### 4. Event Timeline (TicketDetail.tsx bottom ~30%)

Per D-06, D-08: Collapsible vertical timeline.

**Timeline structure:**
```
● Created         ← event icon + type
│ 10 May 2026, 09:15 IST
│ Ticket created by [Author Name]
│
● Assigned
│ 10 May 2026, 09:16 IST
│ Auto-routed to [Handler Name] (Infrastructure category)
│
● StatusChanged
│ 10 May 2026, 10:30 IST
│ Status changed from Open to InProgress by [Actor Name]
│
...
```

- Vertical line: `border-l-2 border-border` connecting events
- Last event: `last:border-transparent` (no trailing line)
- Icon circles: `w-6 h-6 rounded-full bg-surface border-2 border-border` positioned at `-translate-x-1/2`
- Icons inside circles at size 12 (`<Icon size={12} className="text-text-muted" />`)

**Event icon mapping (D-08):**
| Event Type | lucide-react Icon |
|-----------|-------------------|
| Created | `CirclePlus` |
| Assigned | `UserCheck` |
| StatusChanged | `ArrowRightCircle` |
| Resolved | `CircleCheck` |
| Closed | `CircleX` |
| Reopened | `RotateCcw` |

**Collapse behavior:**
- Toggle button: "Ticket Timeline" heading with `ChevronDown` / `ChevronUp` icon
- Collapsed by default when > 5 events; users can expand/collapse at will
- Animation: framer-motion `<motion.div>` with height animation
- State: `useState(true)` initially, toggled by user

### 5. Admin Tray (TicketDetail.tsx — visible only to admins)

Per D-05 (admin roles: HRAdmin/SystemAdmin/MasterAdmin):

- Appears as a section in the TicketDetail header area (below ticket info, above response thread)
- Label: "Admin Actions" in `text-xs font-medium text-text-muted`
- Actions (horizontal button row):
  - **Reassign Handler** button (secondary variant) — opens Modal with handler selection
  - **Force Close** button (danger variant) — opens confirmation Modal
  - Status override dropdown (secondary) — direct status change to any valid state

**Reassign Modal:**
- Title: "Reassign Ticket"
- Content: staff/role selector (simple search input + filtered list — full StaffPicker deferred to Phase 4)
- Submit: "Reassign" primary button
- On success: calls `helpdesk_assign_ticket` RPC, refreshes data

**Force Close Modal:**
- Title: "Force Close Ticket"
- Content: "This will immediately close the ticket regardless of its current status. This action cannot be undone."
- Submit: "Force Close" danger button
- On success: calls `helpdesk_update_status` RPC with target "Closed", refreshes data

### 6. Master-Detail Layout (Helpdesk.tsx)

- Left panel: `w-96` (384px) on desktop, full-width on mobile
  - Contains: assignment tabs → filter bar → ticket list (scrollable)
- Right panel: `flex-1`
  - Contains: TicketDetail rendered inline, or empty state placeholder
- Selected ticket: highlighted in left panel list (`border-l-2 border-terracotta`)
- Mobile: list view by default; tap ticket navigates to `/helpdesk/:ticketId` (full-page detail with back button)

**Empty state (no ticket selected):**
```
┌─────────────────────────────────────┐
│                                     │
│           [MessageSquare icon]      │
│      Select a ticket from the       │
│    list to view its details and     │
│            responses.               │
│                                     │
└─────────────────────────────────────┘
```

### 7. Loading States

- **Ticket list loading:** 5-7 skeleton rows (use `Skeleton` component) with shimmer animation
- **Ticket detail loading:** Skeleton for response posts (3 placeholder cards) + skeleton for timeline (3 placeholder events)
- **Form submission loading:** Button shows spinner (`<Loader2 className="animate-spin" />`) + disabled state
- **RPC call loading:** Button shows spinner; form inputs remain disabled during submission

### 8. Animations (framer-motion)

| Element | Animation | Duration | Easing |
|---------|-----------|----------|--------|
| Reply input expand/collapse | height + opacity | 0.2s | easeOut |
| Timeline expand/collapse | height + opacity | 0.3s | easeInOut |
| Category grid item select | border color + scale (1.0 → 1.02) | 0.15s | easeOut |
| Modal appear | fade + scale (0.95 → 1.0) | 0.2s | easeOut |
| Ticket list item filter | layout animation (AnimatePresence) | 0.3s | easeInOut |
| New response in thread | slide up + fade in | 0.3s | easeOut |

### 9. Responsive Behavior (Claude's Discretion)

- **Desktop (>= 1024px):** Master-detail split-pane; left panel w-96, right panel flex-1
- **Tablet (768px - 1023px):** Left panel w-80 (320px); right panel flex-1
- **Mobile (< 768px):** List view only (`/helpdesk`); tapping a ticket navigates to `/helpdesk/:ticketId` (full-page detail with Back arrow in header). Category grid switches to single column. Filter dropdowns become full-width.

### 10. Keyboard & Accessibility

- All interactive elements focusable with visible focus ring (`focus-visible:ring-2 focus-visible:ring-[#3898ec]`)
- Modal: Escape key closes; focus trapped within modal (follow existing Modal component behavior)
- Reply input: Ctrl+Enter / Cmd+Enter submits reply (Shift+Enter for newline)
- Tab order: logical flow — filters → ticket list → reply input → submit buttons
- Category grid: keyboard navigable (arrow keys between buttons, Enter/Space to select)
- Segmented controls: arrow keys between segments, Enter/Space to select
